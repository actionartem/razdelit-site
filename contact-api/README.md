# Заявки с сайта

Node.js 22 без внешних зависимостей. `POST https://api.simpletracker.ru/razdelit/contact` принимает JSON формы и вызывает Telegram sendMessage. Получатель задан серверной конфигурацией; клиент не может его изменить. Официальный API: https://core.telegram.org/bots/api#sendmessage.

Сервис `razdelit-contact` работает отдельным системным пользователем, слушает только `127.0.0.1:19387`, ограничен по памяти и CPU. Файлы: `/opt/razdelit-contact/server.mjs`, `/etc/systemd/system/razdelit-contact.service`. Секреты `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` находятся в `/etc/razdelit-contact.env` с правами 600, владельцем root. Не копируйте этот файл в репозиторий.

Nginx передаёт только точный путь `/razdelit/contact` новому сервису. Остальные маршруты API работают как прежде. Используется существующий сертификат api.simpletracker.ru, настройки HAProxy/VPN/DNS не меняются. Перед добавлением маршрута сохранена копия nginx-конфигурации; изменения проверены `nginx -t`, применены reload.

Проверки: `node --test contact-api/server.test.mjs`. Ограничения: 8 КБ на запрос, 5 запросов с адреса за 10 минут, 100 отправок за час суммарно, разрешённые origin сайта. CORS не заменяет защиту от ботов; ограничения частоты и скрытое поле уменьшают простой спам. В журнал не записываются тело заявки и токен.

UUID заявки предотвращает повторную отправку в рамках работающего процесса на протяжении суток. При неизвестном результате Telegram обработчик не повторяет отправку автоматически. Дедупликация и ограничения хранятся в памяти и сбрасываются при перезапуске; постоянной очереди нет. HTTP-origin разрешён для текущего переходного состояния сайта; запрос к API всегда HTTPS. После включения HTTPS на GitHub Pages можно удалить HTTP-origin.

Обновления backend развёртываются отдельно от GitHub Pages. Чтобы откатить подключение, убрать точный location из nginx, проверить конфигурацию и выполнить reload; затем остановить только razdelit-contact. Не заменять другие конфигурации и сервисы.
